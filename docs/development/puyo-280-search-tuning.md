# PUYO-280：単独本線探索のパラメータ調整

この作業では `nextgen_tactic_manager` だけを調整する．PUYO-266 の正式判定は，単独の eスポーツ積み・4 色・60 手以内で実際に発火した最大連鎖数を用いる．30 個の未使用配牌を各 2 回実行し，1 回目の平均最大連鎖数 10 以上，不当な小発火 0，回避可能な窒息 0，再現不一致 0 を要求する．証拠不足は合格に数えない．2 回目は再現確認であり，独立サンプルとして平均へ加算しない．95,000 点モードの結果は別の改善指標とする．

## Ama との対応と固定する項目

Ama の公開実装の `build` 重みは，連鎖見込み，連鎖を伸ばせる余地，キーぷよ，接続候補，形状，ちぎり，無駄消しなどを評価する．チューナーは，同じシードで比較し，95,000 点到達の有無と実発火スコアを重視する．出典は [Ama の beam 評価](https://github.com/citrus610/ama/blob/main/ai/search/beam/eval.cpp)，[公開設定](https://github.com/citrus610/ama/blob/main/config.json)，[チューナー](https://github.com/citrus610/ama/blob/main/tuner/tuner.h)．実装・特徴量・スコアの単位が異なるため，Ama の重み数値を転記しない．

本モデルでは，`potential_chain_count` が見込み連鎖数，`potential_chain_score` がそのスコア，`required_key_count` が発火キーの必要量，`remaining_link_2/3` と `connection_candidate` が伸長余地，`danger_ratio` と `hidden_row_puyo` が危険度，`tear` と `waste` が形と消費の損失に対応する．24 項目中，変更するのは見込みスコア・危険比率・小発火コストの 3 項目だけとし，残り 21 項目は既存値を固定する．探索の深さ 16，幅 250，代表未来 6，展開上限 600,000，template 128，response 256，公開情報境界も固定する．

既定の重みは `train/config/v1_7_chain_structure.yaml` にあり，連鎖見込み 1 段あたり 45,000，見込みスコア 1 点あたり 0.05，危険比率あたり -20,000，小発火 -10,000 である．`score95000` モードは探索中と戦術選択の双方で 95,000 点を発火目標とするため，10 連鎖未満での窒息が増えた．単純な発火目標の引き上げだけでは足りない．

## 探索手順

1. 既存 60 手評価の失敗例と成功例を**調整用**に使い，候補を同じ配牌で対比較する．この集合は正式判定には使わない．
2. まず見込みスコアの重みを 0.05 から引き上げる．次に危険比率と小発火コストを組み合わせる．連鎖数の見込みとスコア見込みの両方を保つ候補だけを残す．
3. 各候補について 2 つの発火目標を評価する．目的関数は辞書式で，正式条件の不合格件数，平均最大実発火連鎖数 10 未満の不足量，窒息件数，小発火の未分類件数を先に減らし，次に実発火スコアの平均・95,000 点以上の件数を増やす．実発火ではない探索予測スコアは目的値に含めない．
4. 設定を固定して commit し，未使用の 30 配牌を事前登録して各 2 回実行する．評価器の事前確認に使用した配牌 1092 も除外する．実行後に正式配牌を見て再調整した場合は別コホートを取り直す．各 run の公開入力，決定，実際の連鎖，固定設定，native binary identity，tick replay と品質分類を保存する．

スクリーンは探索上の仮説検証であり，その数値だけで PUYO-266 を COMPLETE にしない．正式判定では 10 連鎖以上の実発火時点，60 手到達，または game over で止める．同じ 60 手境界の 95,000 点目標モードを別に実行し，実際の最大スコアと窒息件数を補助指標として記録する．

### 調整用 12 配牌の中間結果

旧設定の 10 連鎖モードは平均最大 9.17 連鎖，平均最大実発火スコア 38,428 点だった．`potential_chain_score=0.25`，`danger_ratio=-60000`，`premature_fire=-16000` にすると，同じ 12 配牌で平均最大 10.67 連鎖，平均最大実発火スコア 53,179 点，窒息 0 件となった．スコア重み 0.5 は平均最大 10.42 連鎖，平均最大実発火スコア 50,576 点だったため，正式 10 連鎖モードは 0.25 を選ぶ．いずれも調整に使った配牌であり，正式な達成証拠ではない．

95,000 点を厳密な発火条件とするモードでは，旧設定が同じ 12 配牌で平均最大 2.92 連鎖，平均最大実発火スコア 7,591 点，窒息 9 件だった．スコア重み 0.5 と上記の危険・小発火コストでは，平均最大 4.25 連鎖，平均最大実発火スコア 18,719 点，窒息 6 件，95,000 点以上の実発火 1 件となった．厳密なスコア目標は依然として不安定であり，10 連鎖モードの正式合格と混同しない．12 連鎖で発火を許す補助候補も 4 配牌で試したが，厳密なスコア目標より一貫して優れた結果にはならなかったため採用しない．

## 再現コマンド

配牌ファイルの正規のパスを `--tsumo-source` に指定する．正式評価では commit 済みのソースと，その commit からビルドした専用 native wheel が必要である．`init` 後は設定やコードを変更せず，worker は配牌と反復ごとに別プロセスで起動する．

```bash
.venv/bin/python -m eval.nextgen_tuned_solo_gate init \
  --output runs/puyo-280-formal-v1 \
  --tsumo-source /home/sion2000114/.cache/puyo-s15/haipuyo.txt
.venv/bin/python -m eval.nextgen_tuned_solo_gate run-all \
  --output runs/puyo-280-formal-v1 --jobs 6
.venv/bin/python -m eval.nextgen_tuned_solo_gate report \
  --output runs/puyo-280-formal-v1 --verify-replays
```
